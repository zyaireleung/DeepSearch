# 文档写入总则

库里每份 md 都是**某个写入者**按**某种形态**写出来的。动手前先认出属于哪一种：
形态认错，就会把别的写入者的东西覆盖掉 —— 这是这个库最容易出事的地方。

## 一、三种形态

| 形态 | 一句话 | 幂等键 | 旧内容 |
|---|---|---|---|
| 整页写入 | 整个文件的内容都由这次写决定 | 路径 | 不保留，整页替换 |
| 页内追加 | 只往末尾加 | 无（靠内容去重） | 只加不改 |
| 局部更新 | 只替换中间一段或几个键 | 段落锚（标题 / 首句 / 轮数） | 只动那一段 |

「新建」和「覆盖」是同一个动作：同一路径再写一次就是覆盖，旧正文不保留。
唯一的例外是脚本页按自己的幂等键增量续写（会话摘录的蒸馏段），那不是 agent 的路径。

一句话判据：只动末尾 → 页内追加；只动中间一段 → 局部更新；其余 → 整页写入。

## 二、哪些页不能手改

| 写入者 | 写什么 | 能手改吗 |
|---|---|---|
| agent 工具 | note / correct / learn / page 四条路径 | 可以，但要走工具（绕过就没有变更记录和回滚） |
| 脚本与定时任务 | 会话摘录、主题档案、90 系统文件、流水 | 不能，改了会被下次重建冲掉；要改就改它的输入 |
| 人 | `主题档案清单.psv`、`canonical_sources.psv`、`自进化钥匙.md` | 这些本来就是给人改的 |

页里有 `status: generated`，或是主题档案这类脚本重建页，就别手改 —— 改它的输入。

## 三、三条硬底线

1. **写之前先分形态**。一句话用 note，一页文档用 page，改旧结论用 correct。选错工具会写坏库。
2. **改旧结论要留痕**。旧页不删，标 `superseded` 并写 `superseded_by`；新说法写进纠正页。靠链，不靠擦掉。
3. **不搬原文**。写进来的必须是自己的话；网页、文件、工具输出里的字一律不搬。
   资料页要留证据时，留必要短引并标来源，不整篇搬。
   落盘会过脱敏，但脱敏是兜底，不是许可。
